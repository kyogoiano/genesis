## Gradle build

The Gradle wrapper pins Gradle 8.14.5, which supports running Gradle on Java 8.
The production modules target Java 8 bytecode. Run these commands from the
`genesis` directory:

   ./gradlew build

`./gradlew build` runs the client module's unit tests, compiles all dedicated
integration-test sources, and runs the embedded-container integration-test
subset. To run only the client tests:

   ./gradlew :client:test

The client tests include Swing tests and therefore need a working graphical
environment. The tests module uses embedded Apache OpenEJB 8.0.16, which runs
on Java 8 and supports the project's EJB 2.x home interfaces. Run its selected
integration tests with:

   ./gradlew :tests:integrationTest

The current task runs the embedded EJB smoke test and non-weaving tests for
annotations, paging, converters, and bundles. All integration sources compile,
but the full legacy suite is not yet enabled: it needs AspectWerkz bytecode
weaving, and the 2.1 compiler fails on this project. The proposed
`org.codehaus.aspectwerkz:aspectwerkz:2.2.2` and `2.2.3` artifacts are not
available from Maven Central. Tests requiring those aspects remain excluded
until a compatible weaver is selected.

Dependencies are resolved from Maven Central except the historical
`reusable-components-20060810.jar` and the XDoclet generator, which remain local
because no compatible Maven Central artifacts provide them. Gradle invokes the
existing Ant `server:ejbdoclet` target to generate EJB interfaces. The refreshed
Commons and Taglibs dependency versions are centralized in
`gradle/libs.versions.toml` and shared between production and test configurations.
Hibernate is upgraded to 5.6.15.Final, with the matching `javax.persistence`
2.2 API. Its legacy Criteria API remains in use as a compatibility bridge;
the dedicated Hibernate tests compile, but running them still requires the
legacy integration-test runtime setup described above.

The old Ant build remains available for legacy test, deployment, and site tasks.
Those tasks require the external JBoss installation and configuration described
in the historical Ant instructions, and continue to use the dependency JARs
under `lib/` and `../xdoclet/dist/`.

The Ant build files are retained because `build.xml` provides EJB generation
and legacy targets, `build_dist.xml` assembles the distribution, and
`master_build.xml`, `desktop_build.xml`, and `web_build.xml` are used by the
sample-project build templates. They are not unused Gradle leftovers.
