## Gradle build

The Gradle wrapper pins Gradle 8.14.5. Build with JDK 11 or newer; production
modules target Java 11 bytecode. Run these commands from the `genesis`
directory:

   ./gradlew build

`./gradlew build` runs the client module's unit tests, compiles all dedicated
integration-test sources, and runs the embedded-container integration tests.
To run only the client tests:

   ./gradlew :client:test

The client tests include Swing tests and therefore need a working graphical
environment. The tests module uses embedded Apache OpenEJB 8.0.16 and deploys
the executor through EJB 3 business interfaces. Run its integration tests with:

   ./gradlew :tests:integrationTest

The integration test build uses AspectJ 1.9.21 for post-compile weaving. The
weaver processes the project classes and Thinlet dependency before tests run.
The test task excludes the abstract `TestCase` helper and `ValidatorTest`; the latter requires a
`validation.xml` fixture that is not present in the repository.

Dependencies are resolved from Maven Central except the historical
`reusable-components-20060810.jar`, which remains local. The executor uses EJB
3 business interfaces; its interfaces are regular sources and no longer require
XDoclet generation. The refreshed Commons and Taglibs dependency versions are
centralized in `gradle/libs.versions.toml` and shared between production and test configurations.
The client uses the Servlet 3.1 API as a compile-only dependency because a web
container supplies it. Apache Taglibs Standard 1.2.5 is the latest release in
the `javax` namespace and remains compatible with these APIs. The scripting
module uses the Expression Language 3.0 API and GlassFish reference
implementation instead of the deprecated JSP EL and Commons EL APIs. Genesis
selects the GlassFish implementation directly so the host container's EL
provider setting cannot interfere with function argument conversion.
Hibernate is upgraded to 5.6.15.Final, with the matching `javax.persistence`
2.2 API. Its legacy Criteria API remains in use as a compatibility bridge.

Ant remains available for other legacy tasks. Its EJB 2.x server compilation
and home-interface generation, aspect compilation, annotation preprocessing,
weaving, and test workflows are retired. Use Gradle to compile the EJB 3 server
module, build AspectJ, and run tests. The legacy sample-project Ant templates
remain for reference, but their aspect-dependent build and deployment flows
are retired.

The Ant build files are retained because `build.xml` provides other legacy
targets, `build_dist.xml` assembles the distribution, and
`master_build.xml`, `desktop_build.xml`, and `web_build.xml` are used by the
sample-project build templates. They are not unused Gradle leftovers.
